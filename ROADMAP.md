# Roadmap проекта Hopper

## Этап 1. MVP / v0.1: Ядро конвейера, многопоточность, работа с HTTP и ClickHouse

### Что реализую

- HTTP-вход: неблокирующая отправка события в Fan-out
- Базовый pipeline: несколько встроенных процессоров (валидация полей,
дедупликация, парсеры), берущих события из Fan-out и отдающих в Fan-in
- Шардированный кеш для дедупликации и будущих процессоров
- Батчинг событий: получение обработанных событий из Fan-in, сохранение их в
буффер
- Адаптер ClickHouse: батчевая вставка в заранее созданную миграцией таблицу
- Graceful Shutdown: корректное многоступенчатое завершение работы при получении
SIGINT / SIGTERM без потери последнего батча

### Definition of Done

Сервис поднимается в `docker compose` вместе с ClickHouse, выдерживает залп из
50 000 запросов из нагрузочного скрипта, укладывает их пачками в БД, `go test
-race ./...` и бенчмарк проходит

## Этап 2. v0.2: Конфигурируемый пайплайн и отказоустойчивость

### Что реализую

- Паттерн Factory: каждому процессору соотвествует строковое имя и функция-
фабрика, принимающая настройки и возвращающая интерфейс `Processor`
- Декларативная сборка из YAML: сервис читает конфигурацию и создает по ней
слайс `[]Processor`, используемый для pipeline обработки события
- Сетевой процессор с `singleflight`: модуль обогащения события по HTTP со
встроенным `singleflight` и кешем
- Отказоустойчивость записи: если ClickHouse упал, воркер записи после N
ретраев сбрасывает батч в файл на диске, фоновая горутина досылает его после
восстановления БД
- Dead Letter Queue: при фатальных ошибках события сохраняются в DLQ таблицу
ClickHouse

### Definition of Done

Можно поменять порядок процессоров или отключить их в `config.yaml`, перезапустить
сервис и он будет работать по новой цепочке, сервис работает без ошибок если
ClickHouse упал, если процессор вернул ошибку, событие не теряется

## Этап 3. v0.3: Поддержка пользовательских процессоров на Lua из конфигурации

### Что реализую

- Поддаржка Lua процессоров: возможность написать в конфигцрации сервиса свой
процессор на Lua
- Пул виртуальных машин: сохранять вирутальные машины Lua в `sync.Pool`, чтобы
не пересоздавать их каждый раз и безопасно запускать Lua-процессоры из разных
горутин
- Защита от зависаний: установка таймаута в контекст Lua-VM, чтобы
пользовательский скрипт не мог заблокировать воркера навсегда

### Definition of Done

Сервис выполняет процессор из `config.yaml`, написанный на Lua инлайн-скриптом,
процессор работает под нагрузкой без гонок данных

## Этап 4. v0.4: Динамическая схема и маппинг на таблицу пользователя

### Что реализую

- Переход к произвольным пользовательским структурам: безнес-поля в стурктуре
`Event` заменяются на карты `Payload` и `Meta` (`map[string]any`)
- Рефакторинг встроенных процессоров: отвязка от имен полей и получение
целевых полей из конфигурации
- Маппинг в таблицу ClickHouse: в `config.yaml` добавляется секция для описания
таблицы и маппинга колонок (`колонка БД <- поле события`), адаптер ClickHouse
динамически собирает батч в порядке колонок таблицы пользователя

### Definition of Done

Без перекомпиляции Go-кода (только правкой `config.yaml`) сервис настраивается
на прием совершенно разных JSON-схем и успешно раскладывает их в две разные
пользовательские таблицы в ClickHouse. При несовпадении настроенного маппинга
с реальными колонками БД сервис падает при старте с понятной ошибкой (Fail-Fast)

## Этап 5. v1.0: Оптимизация и observability

### Что реализую

- Оптимизация границы между Go и Lua: ленивый маршаллинг данных между Go и Lua
- Оптимизация работы с памятью и GC
- Метрики: экспорт внутренних счетчиков конвейера (RPS, размеры буфферов,
число отброшенных дубликатов, тайминги батчей, количество ошибок)
- Профилирование
- Документация

### Definition of Done

Под нагрузкой в профиле `pprof` и бенчмарках подтверждено снижение количества
аллокаций, написана полная документация в README.md, настроен дашборд в  
Grafana с отображением пропускной способности пайплайна в реальном времени

## Идеи на будущее

- Hot Reload конфигурации без перезапуска сервиса, включая регистрацию новых
пользовательских процессоров
- Поддержка gRPC-стриминга на входе наряду с HTTP эндпоинтом
- Проброс безопасных Go функций в Lua VM (например, доступ из скрипта к
шардированному in-memory кешу)
